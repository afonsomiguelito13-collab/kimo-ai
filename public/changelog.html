Web search 30 Aug 2026

The model can look things up before answering.

  • Magnifier button in the composer toggles it on and off. The setting is remembered.
  • Results are fetched first, then handed to the model as context, which cites them as [1], [2].
  • Sources collapse into a pill under your message, with links and snippets.
  • DuckDuckGo first, Wikipedia as fallback. Searching never blocks the answer — if it fails the question is still asked.
  • Fixed: a long model name pushed the send button off the right edge on phones. The pill now shrinks and ellipsises instead.
  • Five more vendor logos: Claude, Gemini, Qwen, Kimi and Mistral. Nine vendors now carry a real mark, covering 86 of the 103 models.
Why two sources: DuckDuckGo's key-free API only answers topic and definition queries — ask it "who won euro 2024" and every field is empty. Their HTML endpoints would cover the rest but now return an anti-bot challenge, so Wikipedia fills the gap instead.
Key diagnostics 30 Aug 2026

Made authentication failures explain themselves.

  • Test key button in Settings. Makes a real one-token call and reports whether the key actually works.
  • Clear saved key button, to drop a browser-stored key and fall back to .env.
  • Settings now says which key is in use, and warns when a key saved in the browser is overriding your .env.
  • Detects damaged pastes: a leading Bearer, wrapping quotes, embedded newlines, invisible characters, wrong prefix, truncation.
  • A well-formed but rejected key now says so plainly, with a link to issue a new one.
  • Distinguishes a key you just typed from one already saved.
  • This update log and a privacy & terms page, linked from the sidebar.
Why: xKiro's model catalog is public — it returns the full list even with no key at all. Models appearing was never proof of a valid key, which made a 401 look like it came from nowhere.
Safe updates 30 Aug 2026

An updater that cannot leave you with a broken install.

  • update.sh, plus an kimo-update shortcut.
  • Downloads and fully verifies the new build before deleting anything, and restores the old one if the swap fails.
  • Removes the old folder rather than unzipping over it, so files deleted upstream really disappear.
  • Keeps your .env across the swap.
  • Refuses to downgrade, and only stops this app's server, never unrelated ones.
Why: unzip -o overwrites what it finds but leaves deleted files behind, and a stale file can shadow a new one.
